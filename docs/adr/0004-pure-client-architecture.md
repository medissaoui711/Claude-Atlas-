# ADR-0004: اعتماد معمارية SPA جانب العميل كلياً بدون خادم خلفي

## الحالة (Status)
معتمد (Accepted)

## التاريخ (Date)
2026-09-19

## السياق (Context)
أثناء التخطيط لتطبيق **Claude Atlas**، كان السؤال المعماري الأساسي: هل نبني تطبيقاً كامل المكدس (Full-Stack) بخادم Express وقاعدة بيانات سحابية، أم نبنيه كتطبيق صفحة واحدة ثابت (Client-side Single Page Application)؟

## القرار (Decision)
اعتماد معمارية **Client-side Pure React 19 SPA**، يتم تجميعها عبر Vite إلى مجلد ملفات ثابتة (`dist/`)، بحيث يمكن استضافتها على أي خادم ثابت خفيف دون الحاجة لخادم تطبيقات نشط.

## البدائل التي درست (Alternatives)
- **Full-Stack Node.js / Express Server**:
  - *سبب الاستبعاد*: إضافة خادم خلفي نشط يعني تكلفة استضافة مستمرة، نقاط فشل إضافية، تعقيد في النشر، وبطء في زمن استجابة المستخدم دون وجود حاجة تشغيلية حقيقية تتطلب معالجة خادمة.
- **Server-Side Rendering (Next.js / Remix)**:
  - *سبب الاستبعاد*: التطبيق تفاعلي بامتياز ومغلق على محتوى هندسي محدد؛ الـ SSR يضيف تعقيدات إضافية في بيئات الحاويات المضمنة دون عائد ملموس لتجربة المطور.

## التبعات (Consequences)
- **الإيجابيات**:
  - كلفة تشغيل تقارب الصفر.
  - إمكانية العمل بدون اتصال بالإنترنت (Offline First).
  - سهولة النشر على أي منصة (Cloud Run, Cloudflare Pages, GitHub Pages, Netlify).
  - أمان فائق؛ لا توجد خوادم معرضة لهجمات الحقن أو استغلال الثغرات الخلفية.
- **السلبيات**:
  - عمليات المحاكاة (مثل الوكلاء والخطافات) تبقى محاكاة تفاعلية بصرية ولا تنفذ أوامر bash حقيقية على جهاز المستخدم.
